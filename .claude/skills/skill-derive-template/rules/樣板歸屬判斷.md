# Rule 1 - 目標步驟已 READ 樣板就改寫該樣板

- 強度：必須
- 目標步驟之前已 READ 某份樣板時，改寫該樣板，沿用原本的骨架與範例檔名。
- 不另開 `-v2`、`-new` 之類的新樣板，否則 SOP 的 READ 仍指向舊檔，新樣板沒人讀。

## Good Example

- Phase 2 步驟 2 之前已 READ `class-diagram` 樣板，這次要加一段 `## 類別職責`，所以改寫原本的兩個檔案。

```markdown
1. READ `templates/class-diagram.md` 與 `templates/class-diagram.example.md`。
2. WRITE 依 class-diagram 樣板，複製骨架並參照範例填入內容，存入 `docs/design/<功能名稱>-class-diagram.md`。
```

```markdown
plan-with-class-diagram/templates/
├── class-diagram.md          ← 改寫
└── class-diagram.example.md  ← 改寫
```

## Bad Example

- 同樣的修改另開 `class-diagram-v2`，SOP 仍 READ 舊的 `class-diagram`，新加的段落不會出現在產出檔裡。

```markdown
plan-with-class-diagram/templates/
├── class-diagram.md
├── class-diagram.example.md
├── class-diagram-v2.md
└── class-diagram-v2.example.md
```

# Rule 2 - 段落與順序完全相同的產出檔共用同一份樣板

- 強度：必須
- 兩個步驟的產出檔，段落與順序完全相同，才算同一種產出檔；只要有一段不同，就是不同的樣板。
- 目標 skill 的 `templates/` 已有同一種產出檔的樣板時，改寫並共用該樣板，不另開。
- 改寫共用的樣板前，列出所有 READ 該樣板的步驟，在 REPORT 時告訴使用者這次改寫會影響哪些步驟。

| 兩個產出檔 | 段落與順序 | 處理 |
| --- | --- | --- |
| 現況類別圖、目標類別圖 | 都是標題、mermaid 圖、類別職責 | 共用同一份樣板 |
| 現況類別圖、多了 `## 變更理由` 的目標類別圖 | 目標類別圖多一段 | 各自一份樣板 |

## Good Example

- 「重構規劃」skill 的 Phase 1 步驟 3 已依 `class-diagram` 樣板產出現況類別圖。這次要為 Phase 2 步驟 2 的目標類別圖抽樣板，兩者的段落與順序都是標題、mermaid 圖、類別職責，所以共用 `class-diagram`，並記下影響範圍。

```markdown
## Phase 1 — 盤點現況

2. READ `templates/class-diagram.md` 與 `templates/class-diagram.example.md`。
3. WRITE 依 class-diagram 樣板，複製骨架並參照範例填入內容，存入 `docs/design/<功能名稱>-as-is.md`。

## Phase 2 — 提出重構方案

2. WRITE 將重構後的類別結構畫成類別圖，存入 `docs/design/<功能名稱>-to-be.md`。
```

```markdown
refactor-plan/templates/
├── class-diagram.md          ← 共用（Phase 1 步驟 3、Phase 2 步驟 2）
└── class-diagram.example.md
```

## Bad Example

- 同樣的情境另開 `to-be-class-diagram` 樣板。之後只在 `to-be-class-diagram` 加了 `## 介面`，`class-diagram` 沒跟著改，現況圖與目標圖的段落對不上，使用者無法逐段比對重構前後的差異。

```markdown
refactor-plan/templates/
├── class-diagram.md
├── class-diagram.example.md
├── to-be-class-diagram.md
└── to-be-class-diagram.example.md
```
