# Rule 1 - 違反會讓產出錯誤或流程中斷的規則標「必須」

- 強度：必須
- 違反時會出現下列任一結果，就標 `必須`。
- 不因為規則看起來是小細節就降為 `建議`，只看違反時的結果。

| 違反時的結果 | 例子 |
| --- | --- |
| 檔案找不到 | SOP 照 `rules/<檔名>.md` READ 時讀不到 |
| 編號錯亂 | 同一個 Phase 出現兩個步驟 3 |
| 流程走錯 | 「退回步驟 N」指到錯的步驟 |
| 同一件事寫兩次或互相矛盾 | 同一條規則同時存在兩份 RuleFile |
| 產出內容錯誤 | 判準只寫在 SOP 上，RuleFile 裡沒有 |

## Good Example

- 違反時「實作有誤」會退回去重讀規則，而不是修程式，屬於流程走錯，所以標 `必須`。

```markdown
# Rule 6 - 退回引用依新編號修正

- 強度：必須
- 重新編號後，逐一檢查整份 SOP 裡「退回步驟 N」「退回 Phase M 步驟 N」的引用。
```

## Bad Example

- 同一條規則因為「只是改個數字」被標成 `建議`，違反之後流程退回錯的步驟，驗收時也不會被擋下。

```markdown
# Rule 6 - 退回引用依新編號修正

- 強度：建議
- 重新編號後，逐一檢查整份 SOP 裡「退回步驟 N」「退回 Phase M 步驟 N」的引用。
```

# Rule 2 - 違反後結果仍正確的規則標「建議」

- 強度：必須
- 違反時產出與流程都仍然正確，只是比較冗長、比較難讀或比較難維護，就標 `建議`。
- 不因為說得出不照做的壞處就升為 `必須`；壞處沒有落到 Rule 1 的結果，就是 `建議`。

## Good Example

- 違反時只會多一行 READ、後面步驟編號 +1，流程照樣正確，所以標 `建議`。

```markdown
# Rule 3 - 前一步已是 READ 就併入同一行

- 強度：建議
- 被把關步驟的正前方已經是 READ 時，把新 RuleFile 併進那一行，寫成 `READ A 與 B`。
```

## Bad Example

- 同一條規則因為「多一行比較冗長」被標成 `必須`，每條說得出壞處的規則都變成 `必須`，強度分級失去意義。

```markdown
# Rule 3 - 前一步已是 READ 就併入同一行

- 強度：必須
- 被把關步驟的正前方已經是 READ 時，把新 RuleFile 併進那一行，寫成 `READ A 與 B`。
```

# Rule 3 - 違反時的結果只在 REPORT 告知使用者，不寫進 RuleFile

- 強度：建議
- 定強度時想清楚「違反時會怎樣」，REPORT 時和強度一起列給使用者，讓使用者能檢查分級的理由。
- RuleFile 裡只寫 `- 強度：必須` 或 `- 強度：建議`，不附上違反時的結果。

## Good Example

- RuleFile 的強度行保持一行；分級理由只出現在交付時的 REPORT。

RuleFile：

```markdown
# Rule 3 - 前一步已是 READ 就併入同一行

- 強度：建議
- 被把關步驟的正前方已經是 READ 時，把新 RuleFile 併進那一行，寫成 `READ A 與 B`。
```

REPORT：

| Rule | 強度 | 違反時 |
| --- | --- | --- |
| 3 前一步已是 READ 就併入同一行 | 建議 | 多一行 READ，流程仍正確 |

## Bad Example

- 同一條規則把分級理由寫進 RuleFile，執行時多讀一行和規則要求無關的資訊。

RuleFile：

```markdown
# Rule 3 - 前一步已是 READ 就併入同一行

- 強度：建議
- 違反時：多一行 READ，流程仍正確。
- 被把關步驟的正前方已經是 READ 時，把新 RuleFile 併進那一行，寫成 `READ A 與 B`。
```
